# writing-styles

소스·테스트 주석과 `docs/` 문서를 쓰고 고치는 규칙이다. 새 주석·문서는 처음부터 이 규칙으로 쓴다.
기존 코드·문서에 일괄 적용하지 않는다. 고치는 곳에서만 이 규칙으로 맞춘다.

## 적용 대상

| 대상          | 예                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| 소스 주석     | `apps/api/src`, `apps/admin/src`, `apps/demo1/*/src`, `apps/contract/src`                               |
| 테스트 주석   | `apps/api/test`, `apps/*/src/**/*.spec.ts(x)`, `apps/*/src/**/*.integration-spec.ts`, `apps/*/test`     |
| 문서          | `docs/design`, `docs/adr`, `docs/agents`, `docs/requirements`, `docs/guides`, `docs/*.md`, `README*.md` |
| api 한정 문서 | `apps/api/docs/adr`, `apps/api/CONTEXT.md`                                                              |

## 공통 문장 규칙

- 종결: `~한다`체. 명사구 종결은 목록 항목과 표 셀에서 허용한다.
- 한 문장에 한 사실만 담는다.
- 이유·결과·예외를 `—`, `~하므로`, `~해서`로 이어 붙인 긴 문장은 나눈다.
- 나열·순서·조건 분기는 산문 대신 목록으로 쓴다.
- 표 셀도 한 문장으로 쓴다.
- 확인한 사실만 쓴다. 코드를 읽지 않고 설명하지 않는다.
- 사실에 맞아도 어색한 표현은 자연스러운 한국어로 고친다. 번역투·직역투·부자연스러운 조사와 어순이 대상이다.

나눔 예:

```text
전: 전역값은 hard ceiling이므로 namespace 값이 비정상이면 전역값을 쓰고 아니면 둘 중 작은 값을 쓴다.
후: 전역값이 hard ceiling이다.
    namespace 값이 없거나 비정상이면 전역값을 쓴다.
    그 밖에는 둘 중 작은 값을 쓴다.
```

목록 분해 예:

```text
전: 규칙: 계약은 공개 API만 호출하고, 자기 namespace만 쓰며, 정리 코드를 두지 않는다.
후: 규칙:
    - 계약은 공개 API만 호출한다.
    - 자기 namespace만 쓴다.
    - 정리 코드를 두지 않는다.
```

## 소스 주석

### 무엇을 쓰나

- 파일 머리 블록: 파일의 역할, 규칙이 사는 문서, 파일 안 함수들이 공유하는 전제.
- export 선언마다 JSDoc 한 개: `interface`·`type`·`function`·`const`.
- 인터페이스 필드·메서드마다 한 줄 JSDoc. 필드 사이는 빈 줄로 띄운다.
- 코드만으로 안 보이는 것: 이유, 불변식, 호출 순서, 부수 효과, 알려진 한계.
- 코드가 말하는 것은 쓰지 않는다. 이름을 되풀이하는 주석은 지운다.

### 형태

- 첫 문장에 동작을 쓴다. 이어서 조건·부수 효과·이유를 한 문장씩 쓴다.
- 문장 셋 이상이거나 분기가 있으면 목록으로 바꾼다.
- 한 줄로 끝나는 주석은 `/** ... */` 한 줄로 쓴다.
- 여러 줄은 `*` 시작 블록으로 쓴다. 줄 길이는 대략 120자 안쪽이다.
- 선언 밖 지역 설명(함수 안, 테스트 `setup` 안 필드)은 `//`로 쓴다. JSDoc은 선언에만 붙인다.
- 규칙의 출처는 문서로 가리킨다. 문장 끝에 둔다.

```ts
/**
 * namespace 값과 전역값 중 실제로 적용할 상한을 고른다.
 * 전역값이 hard ceiling이므로 결과는 전역값을 넘지 않는다.
 *
 * 선택 규칙:
 * - namespace 값이 `null`이거나 유한한 수가 아니면 전역값을 쓴다.
 * - 그 밖에는 둘 중 작은 값을 쓴다.
 *
 * 규칙은 docs/design/04-namespace-logical-quota.md "계약".
 */
export function resolveEffectiveLimit(namespaceValue: number | null, globalValue: number): number {
```

예의 문서 참조는 형태를 보이기 위한 것이다. 실제 주석에는 존재하는 문서·절을 쓴다.

### 테스트 주석

- 파일 머리 블록: 무엇을 테스트하나, 어떤 환경에서(실제 DB·SQLite·가짜 저장소·jsdom), 규칙이 사는 문서.
- `describe` 앞 `//` 블록: 그 묶음이 고정하는 결함이나 계약, 테스트가 결정적인 이유.
- 이름 있는 헬퍼 함수: JSDoc 한 개. 테스트 본문 안 지역 헬퍼는 `//`.
- 테스트 제목(`it`·`describe`): 주석만 고치는 커밋에서 바꾸지 않는다.
  - 예외: 제목이 존재하지 않는 대상(정의 없는 RQ·문서 절 등)을 가리키면 고친다.
- 상수를 일부러 import하지 않고 리터럴로 두면 그 이유를 쓴다(값이 바뀌면 테스트가 실패하게 한다).

### 계약 검증 코드 (`apps/contract`)

- 파일 머리 주석: 소비자가 기대하는 동작 한 문장. 다른 계약과의 경계가 필요하면 한 문장을 더한다.
- 계약 정의의 `rq`가 요구사항 참조의 원천이다. 같은 RQ 목록을 주석에 다시 쓰지 않는다.
  - 기존 파일의 `대응 요구사항:` 줄은 그 파일을 고칠 때 지운다. 주석만 고치려고 계약 파일을 일괄 수정하지 않는다.
- 실행 방법은 `apps/contract/package.json`의 스크립트가 원천이다. 주석에 다시 서술하지 않는다.

## 참조 표기

허용:

| 표기                            | 뜻                                                                         |
| ------------------------------- | -------------------------------------------------------------------------- |
| `docs/design/NN-*.md` "절 제목" | 규칙이 사는 절. 이 저장소의 design 문서는 절 번호 없이 제목을 쓴다         |
| `ADR-NNNN`                      | `docs/adr/`의 결정                                                         |
| `api ADR-NNNN`                  | `apps/api/docs/adr/`의 결정. 번호가 `docs/adr/`와 겹치므로 접두어를 붙인다 |
| `RQ-NNN`                        | `docs/requirements/file-storage.md`의 요구사항                             |
| `TRP-NNN`                       | `docs/traps/`의 함정 기록                                                  |
| `ROADMAP` 항목 ID(`SEC-02` 등)  | `docs/ROADMAP.md`의 실행 항목                                              |
| `GitHub 이슈 #N`                | 이슈 트래커 항목                                                           |

금지 — 저장소에 남지 않는 곳을 가리키기 때문이다:

| 표기                                        | 대신                                               |
| ------------------------------------------- | -------------------------------------------------- |
| `DELTA-NN`, `DELTA-NN 2차 정정`             | 지운다. 남길 내용이 있으면 결과만 쓴다(예: "실측") |
| `_works/…` 경로                             | 지운다. 작업 폴더는 저장소에 남지 않는다           |
| `docs/superpowers/…`, `.superpowers/…` 경로 | 지운다. `.gitignore` 대상이다                      |
| `.scratch/…` 경로                           | 지운다. 이슈면 이슈 번호로 가리킨다                |
| 없는 파일(`design.md`, `checklist` 등)      | 지운다. 근거는 문장 안에 쓴다                      |

- 참조 문서·경로·ID는 존재를 확인한 뒤 쓴다. 문서 제목이 바뀌면 참조도 같이 고친다.
- "계획서에 따르면", "체크리스트가 밝힌 대로" 같은 소멸한 문서 인용은 근거 문장으로 바꾼다.
- 예외: `docs/agents/rubber-workflow.md`, `AGENTS.md`, 이 문서는 `_works/`·`DELTA`를 설명하는 문서이므로 이 표기를 쓴다.

## 설계 문서

`docs/design/`은 현재 시점의 규칙·계약·근거만 담는다. 작업 이력·측정 로그·이전 구현의 기록이 아니다.

결정 근거는 `docs/adr/`(api 한정은 `apps/api/docs/adr/`), 요구사항은 `docs/requirements/`, 작업 중 발견한 함정은 `docs/traps/`가 원천이다.

### 쓰는 것

- 규칙·계약·불변식.
- 그 규칙이 있는 이유. 한 항목에 이유 하나.
- 규칙이 막는 결함의 재현 조건. 결과 로그는 쓰지 않는다.
- 규칙을 고정하는 테스트·스크립트의 파일 이름.
- 실측 근거는 사실 한 문장. 측정 환경(버전·조건)을 함께 쓴다.
- 채택하지 않은 안은 현재 설계를 이해하는 데 필요한 이유만 쓴다.
- 추정은 추정이라고 밝힌다. 확인하지 않은 것은 확인하지 않았다고 쓴다.

### 쓰지 않는 것

| 쓰지 않는 것                                                 | 대신                                        |
| ------------------------------------------------------------ | ------------------------------------------- |
| 소스 줄 번호·줄 수                                           | 파일·함수 이름                              |
| 파일·테스트·패키지·항목 개수                                 | 이름 목록. 목록이 이미 있으면 개수를 지운다 |
| 실행 결과 로그·ms 분포·표본 수                               | 원천 파일 링크와 실측 사실 한 문장          |
| 이전 구현·옛 구조·"수정 전 코드" 서술                        | 현재 동작                                   |
| "~를 더했다"·"~로 모았다" 같은 작업 이력                     | 현재 동작                                   |
| 날짜(`2026-09-24`)와 "사용자 확정·결정" 귀속                 | 지운다. 결정 기록은 ADR이다                 |
| `DELTA-NN`·`_works/`·`docs/superpowers/` 경로·없는 문서 인용 | 지운다. 남길 내용은 근거 문장으로 쓴다      |
| 채택하지 않은 초안의 나열                                    | 필요한 이유 한 줄                           |

예외:

- 규칙 자체가 수치인 값은 쓴다(상한, 간격). 값의 원천은 상수 이름으로 가리킨다.
- 실측 집합의 크기가 규칙의 근거이면 쓴다. 측정 환경을 함께 쓴다.
- ADR의 `상태` 절은 채택 날짜를 쓴다.
- `docs/requirements/file-storage.md`의 판정 근거는 검증 실행 결과(통과 수 등)를 쓴다. 진행 상태 판정의 근거이기 때문이다.

### 구조·번호

- design 문서의 파일 번호(`NN-*.md`)는 읽기 순서다. 새 문서는 끝 번호 다음에 붙인다.
- 문서 안 절은 번호 없이 제목으로 구분한다. 참조는 파일과 절 제목으로 쓴다.
- 결번은 그대로 둔다. 재번호하지 않는다. 결번은 `docs/design/README.md`에 한 줄로 밝힌다.
- 다른 문서·소스·테스트가 파일 번호나 절 제목으로 참조하는 항목은 이름을 유지한다.
- 파일 이름이나 절 제목을 바꾸거나 절을 지우면 저장소 전체 참조를 검색해 같이 고친다.

### 규칙의 위치

- 규칙·상수는 한 곳에만 쓴다. 다른 곳은 문서와 절 제목으로 링크한다.
- 같은 규칙을 두 문서에 다시 쓰지 않는다. 겹치는 곳을 찾으면 한쪽을 링크로 바꾼다.
- ADR은 결정과 근거를 자체로 완결되게 쓴다. 병합 뒤 사라지는 작업 문서에 의지하지 않는다.
- ADR은 결정 배경으로 이전 구현·이력을 쓸 수 있다. 위 "쓰지 않는 것" 표의 이력 금지 대상이 아니다.
  - "이전 구현" 같은 상대 표현은 그 ADR의 첫 언급에서 대상을 밝힌다.

### 형태

- 이유 문장 하나에 결정·근거·기각안을 이어 붙이지 않는다. 목록 항목 하나에 사실 하나씩 쓴다.
- 진행 순서·번호가 있는 절차는 번호 목록을 쓰고, 항목 안 부연은 하위 목록으로 내린다.
- 표 셀은 문장 단위로 끊는다.
- 수치는 실측 값을 쓴다. 추정치를 쓰면 추정이라고 밝힌다.
- 테스트 제목을 인용하면 실제 `it`·`describe` 제목과 대조한다.

### 점검

design을 고친 뒤 아래를 돈다.

- 이력 표기 잔존 검사. 출력은 이번에 고친 파일에 없어야 한다.
  `grep -nE "사용자 (확정|결정)|20[0-9]{2}-[0-9]{2}-[0-9]{2}" <고친 design 파일>`
- 금지 표기 잔존 검사는 아래 "검증"의 `DELTA` 명령이다.
- `pnpm format:check`.

## 고칠 때

1. 주석을 다시 쓰기 전에 대상 코드를 읽는다. 설명이 코드와 다르면 코드에 맞춰 고친다.
2. 틀린 설명을 찾으면 문체만 바꾸지 않고 내용을 바로잡는다. 커밋 메시지에 밝힌다.
3. 고친 수치는 다시 센다.
4. 문체만 바꾸는 커밋에서는 코드 동작을 바꾸지 않는다. 이름·로직 변경은 별도 커밋으로 분리한다.
5. 테스트 제목은 그대로 둔다. 존재하지 않는 대상을 가리키는 제목만 고친다.
6. 기존 영어 주석은 그 주석을 고칠 때 한국어로 바꾼다. 건드리지 않는 주석은 일괄 변환하지 않는다.

## 검증

| 명령                | 확인                                                |
| ------------------- | --------------------------------------------------- |
| `pnpm format:check` | prettier. 표 열 정렬 포함. `pnpm format`으로 고친다 |
| `pnpm lint`         | eslint                                              |
| `pnpm typecheck`    | 타입. 주석 편집이 코드를 깨지 않았는지              |
| `pnpm test`         | 단위 테스트. 주석 편집 뒤에도 통과해야 한다         |

- 문서만 고쳤으면 `pnpm format:check`만 돈다. 나머지는 소스·테스트 주석을 고쳤을 때 돈다.
- 금지 표기 잔존 검사는 이번에 고친 파일에만 적용한다. 출력이 없어야 한다.
  `grep -nE "DELTA-[0-9]|_works/|\.scratch/|docs/superpowers" <고친 파일>`
- 저장소에는 이 규칙 도입 전에 쓴 금지 표기가 남아 있다. 고치지 않는 파일의 잔존은 이 검사의 대상이 아니다.
