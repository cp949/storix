# TRP-005 SQLite는 varchar 길이를 강제하지 않아 SQLite 통과가 PostgreSQL 22001 안전을 보장하지 않는다

- 상태: ACTIVE
- 적용 조건: 클라이언트가 보내는 문자열(헤더·쿼리·본문)을 `varchar(N)` 컬럼에 저장하는 코드를 추가하거나 바꿀 때.

## 오해하기 쉬운 신호

SQLite 드라이버의 단위·통합·계약이 모두 통과한다.
같은 요청을 PostgreSQL에서 보내면 `value too long for type character varying(N)`(22001)이 나고 500이 된다.
오류 매핑은 22xxx 코드를 분류하지 않아 클라이언트 오류가 아닌 서버 오류로 보인다.
GitHub 이슈 #12가 이 경로로 발견됐다.

## 원인

- SQLite의 `varchar(N)`은 길이 제약이 아닌 타입 선호도다. 초과 값을 그대로 저장한다.
- PostgreSQL은 초과 값을 거절한다.
- 입력 검증 상한(미들웨어·DTO)과 컬럼 길이를 따로 정하면 둘이 어긋나도 SQLite에서는 드러나지 않는다.

## 탐지/회피

- 탐지: 새 입력이 저장되는 컬럼의 `varchar(N)`을 엔티티와 마이그레이션에서 확인하고, 입력 검증 상한과 같거나 작은지 비교한다.
- 회피: api ADR-0041의 기준(확장·대체·거절)으로 입력별 처리를 정하고 상한과 상한+1을 모두 검증한다.
- 회귀 검증: 상한/상한+1 경계는 PostgreSQL 프로파일의 통합 테스트와 계약으로 확인한다. SQLite 프로파일만 실행하면 이 결함을 놓친다.
- 남는 위험: 서버가 생성하는 값(`digest`·`encryption_iv` 등)과 enum 컬럼은 입력 출처로 전수 확인하지 않았다.
