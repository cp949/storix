# TRP-001 경합 계약이 한 분기만 실행하고 통과한다

- 상태: ACTIVE
- 적용 조건: 동시 요청 두 개를 `Promise.all`로 보내 "성공이거나 거부" 중 하나를 허용하는 계약(`apps/contract`)을 쓸 때.

## 오해하기 쉬운 신호

계약이 통과한다. 그러나 요청 지연 차이 때문에 항상 같은 쪽이 먼저 끝나면 다른 분기의 단언이 실행되지 않는다.
`snapshot-create-race` 초안은 교체(저장소 업로드 후 커밋)와 snapshot(작은 JSON)을 동시에 보내 36/36이 201이었다.

## 원인

두 요청의 처리 시간이 다르면 경합 창이 열리지 않는다. 계약이 두 결과를 모두 허용하므로 한쪽만 나와도 통과한다.

## 탐지/회피

- 임시 로그로 분기 분포를 한 번 관찰한다.
- 한쪽만 나오면 한 요청을 먼저 시작해 두고 다른 요청을 반복해, 커밋 시점에 걸치게 한다.
- 실행된 분기 수를 단언한다.
